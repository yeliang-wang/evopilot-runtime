# Runtime v0.10 feedback loop ADR

Accepted for implementation in the reviewed Preview scope on 2026-11-25.

Runtime owns project-scoped orchestration and durable receipts. The existing Codex Expert and HTTP MCP route remains the human configuration and inspection entry. Slack Socket Mode is the first platform adapter. The user deferred live Slack E2E; the independently authenticated callback reference exercises normalized ingress, notification and review actions in the integrated acceptance journey. Linear is the issue owner, Cursor Cloud the coding executor, published Harness the rule owner, and GitHub the final authority over branch rules and merge. Ontology is an optional published read dependency.

Channel event identity is stable across credential rotation. Authenticate at the adapter boundary, then use the platform installation, tenant, conversation and event identity with an exact payload digest. A repeated event reuses its result. A changed payload under the same event identity is a conflict. Bind project routes explicitly, retain original message IDs, and isolate tenants. Treat feedback text and adapter payloads as data. Pass only authorized content to the selected coding Agent.

For each external mutation retain an original intent and correlation identity before dispatch. Reconcile that identity with the actual provider before any resumption following uncertainty. Preserve the same issue, run identity when reconciling, and original PR. Keep release or deployment authority separate from code merge. Use protected credential references.

Timed merge is an additive authority. An authenticated operator preauthorizes the selected project, repository, branch, low-risk paths, required evidence, named reviewers, scope and expiry. A durable review window starts after acknowledged notification. Bind it to the exact PR, candidate and base SHA, validation evidence and policy revision. A confirmed veto, changed candidate or authority, or uncertain review-channel continuity blocks the window. Serialize accepted veto and merge reservation. Retain a veto against the exact PR head even across later review windows. Use Runtime admission time and block on uncertain event coverage. Commit the original claim before contacting GitHub and reread the original outcome after uncertainty. Enforce GitHub branch protection and expected head. Confirm merge before closing the issue or replying with success.

Compatibility and rollback preserve all published v0.9 bytes and acceptance records. Start v0.10 acceptance from a fresh private root. An old installation gains no worker, timed merge policy or provider permission by upgrading. A stopped isolated backup and restart test must precede any proposed migration, which is a separate decision. Shut off intake and outbound dispatch on rollback; retain intent, state and uncertain receipts for read-only reconciliation.

A separate externally hosted workflow system could perform intake and coordination, with Runtime receiving receipts. Keeping dispatch and authority in the existing owner is selected because the review window, audit and original claim can share the scoped authoritative state.
