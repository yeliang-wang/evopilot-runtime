# Runtime v0.10.0 Preview plan

This accepted target starts from the published v0.9.0 Runtime tag (`81777f07e856ba5a3615b373de5f6709dc3b3e9b`). It adds a feedback-to-PR lifecycle in one dedicated project. Slack remains the first platform adapter. The user deferred live Slack E2E because a test channel is unavailable. The authenticated callback reference implementation is the representative acceptance channel, with actual Linear, Cursor Cloud and GitHub services. Record Slack protocol checks and the deferred live case separately. Real Feishu and WeCom qualification has its own future evidence. Codex uses the existing Runtime Expert and HTTP MCP for first-run configuration, exact activation and readback. The Runtime worker can continue independently after Codex closes.

The initial flow preserves one issue and workflow instance from an authorized feedback message. Information requests continue the original case. A verified fix opens or updates the same PR, and independent verification is pinned to its head and base. An acknowledged notification opens the actual sixty-minute review window. Changes requested return to repair. After expiry the current policies and evidence are rechecked; GitHub confirms the authorized rebase merge before work closes.

| Milestone | Required outcome |
| --- | --- |
| M1 | Actual Codex Desktop Expert configuration and activation, plus DASH-01 configuration browser acceptance |
| M2 | Slack protocol checks and the authenticated callback reference for intake, reply, Linear identity and needs-info resumption. Live Slack is deferred. |
| M3 | Actual Cursor reproduction and PR, independent functional verification and one repair cycle, plus continuation with Codex closed |
| M4 | Candidate-bound veto, expiry, branch protection and actual sixty-minute merge |
| M5 | Complete integrated reference-channel feedback chain, recovery of uncertain mutations, and DASH-02 path/return-edge monitoring |
| M6 | Separately approved exact GitHub prerelease, anonymous asset verification, isolated reinstallation, representative journey and bilingual docs |

The two approved mockup fingerprints are recorded in the acceptance inventory. On `/lifecycle`, keep the flow graph above YAML and save a draft without activating it. On `/monitor`, project run events into the current node, visited path, actual return edge, reason and authority-independent countdown. Keep the monitor read-only. Reconnect from the original cursor or refresh a verified snapshot on a gap. Actual screenshots and event receipts establish acceptance.

The final English and Chinese README include the user-supplied external workflow reference and source attribution. Keep evidence, credentials, provider bindings and exact decisions private. Linked proposals are not claimed as completed acceptance.
