# Runtime v0.10.0 Preview plan

This accepted target starts from the published v0.9.0 Runtime tag (`81777f07e856ba5a3615b373de5f6709dc3b3e9b`). It adds a feedback-to-PR lifecycle in one dedicated project. The only real-use E2E route is a signed-in Codex Desktop conversation using the installed Runtime Expert and the actual Runtime HTTP MCP. Bind the signed-in identity, observed model, installed package and original HTTP request receipts to the exact candidate. Validate configuration, retain the exact YAML draft, restart the isolated Runtime and read back the same draft after reconnecting. Use isolated protected test bindings and fixture provider data to exercise exact activation. The named project owner records the actual decision for the exact candidate, and the Expert reads back the activation receipt and active configuration.

Slack Socket Mode remains the first platform adapter. The live Slack case `CHANNEL-REAL` is deferred. Real Linear, Cursor Cloud and GitHub App operations are outside this Preview’s acceptance scope. Local automated tests exercise the Slack protocol, authenticated callback reference, provider contracts and worker continuation after client disconnect. Live Feishu and WeCom qualification requires future evidence.

The initial flow preserves one issue and workflow instance from an authorized feedback message. Information requests continue the original case. A verified fix opens or updates the same PR, and independent verification is pinned to its head and base. An acknowledged notification opens the actual sixty-minute review window. Changes requested return to repair. After expiry the current policies and evidence are rechecked; GitHub confirms the authorized rebase merge before work closes.

| Milestone | Required outcome |
| --- | --- |
| M1 | `EXPERT-REAL` verifies configuration and exact owner-approved activation through the installed Expert. `DASH-01` checks the configuration design in a local automated browser. |
| M2 | Local Slack protocol and authenticated callback fixtures check intake, reply, original issue identity and needs-info resumption. `CHANNEL-REAL` remains deferred. |
| M3 | Local fixtures check the coding-adapter run, original PR, independent verification, a repair cycle and worker continuation after the client disconnects. |
| M4 | Local fixtures and a controlled clock check exact-candidate veto, expiry, branch protection and the full sixty-minute merge rule. |
| M5 | Local fixtures check the complete reference-channel loop and recovery of uncertain mutations. `DASH-02` checks the monitor design, path and return edge in a local automated browser. |
| M6 | `DOCS-CI` verifies exact candidate CI and bilingual docs before release. Exact GitHub prerelease publication requires separate approval. `PUBLIC-READBACK` verifies the public tag, prerelease and anonymously downloaded asset digests. `FRESH-REPLAY` repeats the actual Expert and HTTP MCP journey after installing the exact downloaded package into a fresh private root. |

The acceptance inventory records both approved mockup fingerprints. On `/lifecycle`, keep the flow graph above YAML and save a draft without activating it. On `/monitor`, project run events into the current node, visited path, actual return edge, reason and authority-independent countdown. Keep the monitor read-only. Reconnect from the original cursor or refresh a verified snapshot on a gap. Retain screenshots and matching event receipts from local automated browser runs for both designs.

The final English and Chinese README include the user-supplied external workflow reference and source attribution. Keep evidence, credentials, provider bindings and exact decisions private.
